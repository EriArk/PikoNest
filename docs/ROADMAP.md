## Цель и граница выпуска

На Android-портативке пользователь может **играть**, а отдельно — **создать игру
с нуля, нарисовать ресурсы, собрать поле/сцену, задать правила, добавить анимацию,
эффекты, SFX и музыку, проверить, исправить, переиспользовать и экспортировать**.
Обычные картриджи открываются в официальном PICO-8 вне PIKOOS.

Полноценный Android-выпуск включает общие Code/Sprites/Map/Sound, создание без героя,
базовые анимацию/камеру/параллакс/VFX, библиотеку ресурсов, механики, контекстную
справку, проекты/ремиксы, Play и внешние лаунчеры, первый запуск и восстановление.
Шаблоны помогают начать, но не включают и не выключают инструменты.

Linux, Link Play, online bridge и персональные онлайн-картриджи остаются дальнейшими
направлениями. Они не блокируют локальный Android-выпуск. Продвинутые watch/replay/
debugger и публикация веб/бинарных игр требуют отдельного решения о составе;
базовые диагностика и экспорт обычного проекта входят в обязательный путь.

**Релизный барьер:** GitHub APK Release/prerelease — только после явного подтверждения
владельца, что результат полностью устраивает, и разрешения выпуска. Прохождение
тестов, этот план, source push и установка локальной APK такого разрешения не дают.

## Completion path

Этапы — проверяемые результаты, не даты или проценты. Все M0–M6 остаются открытыми
как продуктовые этапы; внутри уже есть частично реализованные задачи.

| Этап | Завершённый пользовательский результат | Задачи | Критерий перехода |
| --- | --- | --- | --- |
| **M0. Основа общих редакторов** | Работающие проекты/инструменты сохраняются при развитии приложения | A01–A05, базовые P01/P03 | Зафиксированы производственные границы, общая транзакция правки/черновика/истории и переносимая модель без обязательного героя |
| **M1. Своя игра из пустого картриджа** | Ввод, состояние, цель, повторный старт; изменение правил и экспорт | C01–C03, C06, минимальный G04, первые H01/H02; существующие save/runtime/export | ACC-01 целиком в приложении с контроллера, без изменения исходников разработчиком, терминала и обязательной клавиатуры. Готовая заготовка не засчитывается как создание с нуля |
| **M2. Мир и движение** | Собственные ресурсы, карта/поле, анимация, камера и движущийся фон | G01–G04, N01–N03, M01–M03 | ACC-02: оригинальная сцена и вариант без героя; совместная gfx/map-память сохраняется; обычный PICO-8 воспроизводит результат |
| **M3. Звук, правила и выразительность** | Свои SFX/музыка, события/противники/UI, частицы и переходы | S01–S05, M04–M06, расширение M01/M02, H01–H03 | ACC-03: звук и эффект связаны с игрой, работают с музыкой; доступны остановка, отмена и ручная правка Lua |
| **M4. Переиспользование и полноценные проекты** | Разобрать игру, сделать ремикс, перенести ресурсы, собрать главы и экспортировать весь проект | P01/P04–P08, C04–C05, B01–B05, T01 | ACC-04/05: зависимости переносятся целой отменяемой операцией; проект работает без исходной библиотеки; главы и сохранения переживают перезапуск |
| **M5. Самостоятельное приложение** | Купленный runtime, папки, Play/Splore/создание на чистом устройстве | R01–R08, P02/P03/P08, L01–L03, A06 | ACC-06/07: без ручной настройки среды; офлайн-игра, внешние лаунчеры, потеря доступа и сбой обновления имеют восстановление |
| **M6. Приёмка Android** | Реальные проекты разных жанров без технических обходных действий | Q01–Q06 и обязательные задачи M0–M5 | ACC-08 и повтор всего набора: контроллер, экраны, производительность, сохранность, документы; отдельное одобрение владельца |

**M5 — параллельное направление работ.** Текущий доказанный runtime позволяет
начать M1 на Retroid. Не откладываем все редакторы до окончания инфраструктуры;
не откладываем и инфраструктуру до релиза. Пользовательские папки/восстановление
нужны до длительных реальных проектов M4, чистая установка — до M6. Отсутствующий
контракт становится узкой зависимостью задачи, а не поводом для общего переписывания.

H01–H03 развиваются вместе с инструментами: объяснение выполненного действия
появляется в том же срезе. Совместимость, контроллер, отмена и восстановление
проверяются при каждой новой операции, а не впервые на финальной приёмке.

**Языки (решение владельца 2026-10-03):** позже полностью перевести интерфейс,
подсказки, ошибки, справку и пользовательскую документацию на английский (Q07).
После этого — выбор распространённых языков (Q08), включая сохранённый русский.
Набор дополнительных языков и выпуск для них пока не зафиксированы. Каталог строк
должен быть переносимым; шрифты, длина текста и управление проверяются для каждой
локали. Имена API и пользовательские проекты перевод не изменяет.

## Ближайшая очередь

Первый срез A01/A02 → C01.1 реализован в lab 0.0.31:
[границы решения](EDITOR_FOUNDATION.md), [проверки](design/android-code-31/README.md).
Общий Lua-черновик уже работает; родительские задачи и M1 остаются открытыми.

1. **A01 + A02:** ограниченное решение о развитии host/core и общий контракт
   правки. Сравнить реальные ограничения/стоимость, записать решение; не менять
   framework молча и не переписывать доказанные инструменты ради нового примера.
2. **C01:** превратить вкладку «Код» в редактор обычного Lua: вставка, удаление,
   выделение, сохранение, отмена, Test и возврат. Пустой картридж получает
   собственный видимый результат через UI.
3. **C02 + начальная C03 + H01/H02:** конструкции, известный API и объяснения;
   собрать ACC-01 с правилом победы и перезапуском. Это первый сквозной рубеж,
   а не завершение всего редактора.
4. **R01/R03 и P01/P03:** активация/восстановление runtime и проекта. Сбой
   подготовки не ломает редактор. Эти задачи можно брать раньше при реальном
   блокере проверки M1, с сохранением цели первого авторского цикла.
5. **G01/G03/G04 + M01/M02**, затем N01: карта/поле, известное событие, анимация.
   P02/R02 развиваются по согласованным контрактам для самостоятельной установки.

В 0.0.32 выполнен **C02.1**: каталог Lua/API и параметры; игра со счётом, целью и
сбросом создана через UI и запущена официальным runtime. [Свидетельства](design/android-insert-32/README.md).
В 0.0.33 выполнен **C03.1**: выбор общих имён текущего Lua и восьми выражений API
в параметрах вставки. [Свидетельства](design/android-symbols-33/README.md).
В 0.0.34 выполнен ограниченный **C02.2**: формы существующих вызовов с сохранением
нетронутых аргументов/форматирования. [Свидетельства](design/android-parameters-34/README.md).
В 0.0.35 выполнен ограниченный **C03.2**: функции текущего Lua, номер строки,
preview и история возврата. [Свидетельства](design/android-navigation-35/README.md).
В 0.0.36 выполнен ограниченный **C06.1**: отдельная четырёхсекундная проба копии
черновика, текст ошибки, переход к подтверждённой строке tab 0 и повтор после правки.
[Свидетельства и границы](design/android-diagnostics-36/README.md). Полная C06,
включая табы, include mapping и диагностику интерактивного сеанса, остаётся открытой.
В 0.0.37 / Runtime Test 6 выполнен ограниченный **R03.1/Q02**: меню Select/Back,
продолжение и обычное завершение PICO-8 с возвратом к месту запуска. На Retroid
проверены Test, Play, Beacon и Retroid Launcher; ввод — события ADB, физическая
эргономика ещё требует приёмки. [Свидетельства](design/android-exit-37/README.md).
В 0.0.38 / Runtime Test 7 выполнен ограниченный **R03.2**: отдельное наблюдение
за сеансом и явный адрес возврата. Проверены Home/resume, посещение PIKOOS при
живой игре, оба внешних лаунчера и потеря процесса host без потери живого runtime.
[Свидетельства и границы](design/android-return-38/README.md). Общий runtime crash
recovery и физическая приёмка остаются открытыми.
Следующий исполняемый срез — **сквозная ACC-01**: создать новую игру из пустого
картриджа через UI, изменить правило, проверить ошибку, вернуться и экспортировать.
Короткая проба не заменяет полноценный Test; M1 пока не закрыт.
Дополнительные кисти, шаблоны и полировка полки не вытесняют этот разрыв полного
цикла без новой причины.

## Общие условия завершения задачи

1. Доступный путь с контроллера, явные Confirm/Cancel/Undo для изменений;
   touch улучшает путь, но не становится скрытым обязательным условием.
2. Результат — обычные Lua/ресурсы. Стандартной игре не нужны metadata,
   библиотека PIKOOS или каталог механик во время исполнения.
3. Неизвестные данные сохраняются. Неоднозначная привязка ведёт к коду/понятному
   отказу; инструмент не восстанавливает шаблон поверх ручных изменений.
4. Проверены сохранение, ошибка, отмена, повторный вход и возврат из Test.
   Модель, официальный runtime и удобство на устройстве — разные доказательства.
5. Есть уместные тесты, скриншоты/запись результата и фактические ограничения.
   Владелец принимает продукт отдельно от технических проверок.

## После локального Android-продукта

- **X01 Linux:** заменить платформенные адаптеры; сохранить core и проекты.
- **X02 Link Play:** доказать ввод, тайминг, задержки и рассинхронизацию.
- **X03 Online bridge:** доказать транспорт и поведение при его отсутствии.
- **X04 Персональные картриджи:** token, серверный PIN, отзыв, Factory Reset и
  Share Clean после проверки транспорта/round-trip; кодирование token остаётся TBD.
- **X05 Каталог/сообщество:** происхождение, коллекции и явный обмен, без
  обязательного аккаунта для локальной работы.

Эксперименты X не меняют незаметно контракт обычного картриджа.

## Поддержание плана

Статус задач — в BACKLOG, доказательства — в STATUS и `docs/design/`. Перед задачей
проверяем зависимости/checkout; после — обновляем её строку, свидетельство и
следующий пользовательский результат. Отсутствующий инструмент получает задачу
и приёмку, а не считается покрытым шаблоном или сохранением неизвестной секции.

На GitHub при аудите issues/PR/milestones отсутствовали. Локальные ID можно
перенести в issues с сохранением ссылок; не вести два независимых статуса.
Этот план не объявляет редакторы завершёнными и не разрешает APK release.

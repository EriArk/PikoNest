# Android 0.0.40 — поля игровых правил

2026-10-04, база `60b1559`, main. Ограниченный C02.3: обычные условия и
присваивания редактируются через поля с контроллера. Родительские C02/M1,
физическая UX-приёмка и самостоятельный путь новичка остаются открытыми.

## Пользовательский путь

В черновике Lua выбрать строку → L, либо Select → «Поля текущей строки».

- `if score>=5 then`: «Слева», «Сравнение», «Справа». Числовой порог меняется
  стрелками, знак — циклическим выбором с пояснением («равно», «не меньше» и т. д.).
- `score=0`, `local score=0`, `score+=1`: имя и значение. Надпись предупреждает,
  что имя меняется только в этой строке: это не переименование всех использований.
- Поддерживаются также заголовки `elseif`. Составное условие вроде
  `if ready and score<10 then` получает одно поле выражения, без разбора на
  независимые параметры. Исходные скобки сохраняются.
- Внизу «Было/Будет», затем явное «Применить правку». B отменяет форму,
  Start внутри неё не сохраняет и не запускает игру. Одна правка — одна отмена.
- В каталоге добавлена 18-я вставка «if · сравнить значения». Она создаёт
  обычный `if … then … end`; не включает особую механику или runtime API.

Синтаксис сверён с [официальным мануалом PICO-8, Lua Syntax Primer](https://www.lexaloffle.com/dl/docs/pico-8_manual.html#_Lua_Syntax_Primer):
условия, присваивания, local, сокращённое `+=`, сравнения и допустимый `!=`.
Результат проверен пользовательским официальным PICO-8 0.2.7 на устройстве.

## Сохранность и границы

`LuaRule` — переносимый консервативный разбор отдельных строк. Он возвращает
точные диапазоны полей существующему механизму `LuaCall`/`LuaDraft`.
Меняются только отредактированные диапазоны; исходные пробелы, окончания строк,
комментарии, `local`, тело блока и другие секции не перегенерируются.
No-op не меняет каретку/историю. Перед применением проверяется исходная строка,
повторно разбирается результат и проверяются границы всех полей.

Поддерживаемый набор выражений: числа, обычные кавычечные строки, boolean/nil,
имена, скобки, вызовы, чтение полей/индексов, основные арифметические и логические
операторы. Это не полный компилятор: имена/типы/корректность игры проверяет runtime.
Глубина разбора ограничена 64, поля — прежними 256 символами стенда.

Пока нет форм для нескольких команд/присваиваний в одной строке, записи в
табличные поля/индексы, конструкторов таблиц, функций-выражений, длинных строк,
block comments, shorthand `if(x) ...`, других составных присваиваний и полного
набора выражений PICO-8. Строки внутри незакрытых внешних скобок не распознаются
как самостоятельные правила. Это ограничения PikoNest, не PICO-8: обычный Lua-редактор
доступен, неизвестный код не заменяется и не объявляется несовместимой игрой.

Если новое выражение меняет структуру формы (например, `5 or ready` вместо
правой стороны сравнения), Apply отказывается от изменения. Можно явно указать
скобки или вернуться к обычному Lua. Полная замена структуры условия — не задача
этой формы. Однострочный комментарий внутри нового поля не может скрыть остаток строки.

Журнал черновика сохраняет форму, выбранное поле, предложения, палитру и список
имён. Новая форма сравнения добавлена в конец каталога, старые ID не изменены.
Старые журналы продолжают читаться; при восстановлении привязка повторно строится
по исходному Lua. `.p8` не зависит от журнала.

## Проверка на устройстве

Retroid Pocket Classic / Android 14, `DEVICE_SERIAL`, landscape 1240×1080,
density 320; Runtime Test 7 с пользовательским PICO-8 0.2.7 Raspberry Pi ARM64.

1. Через полку сделана «Копия 10» (`remix-0010`) из `blank-0004` предыдущего ACC-01.
   Все правки выполнены через D-pad/A/B/L/Y/R2/Start, инъекцией ADB.
2. Строка 3: форма `score=0` → значение 2, Cancel; повторное открытие показывает 0.
   Затем повторены изменение и Apply. Строка 8: `score+=1` → 2.
3. Строка 21: форма сравнения `score>=5` → порог 8 тремя Right. Без выделения
   символов, экранной клавиатуры или записи Lua разработчиком в файл.
4. Home → force-stop host → открытие → R мастерская → B продолжить.
   Незавершённая форма восстановила порог 8 и фокус поля, прежние две правки сохранены.
5. Компактная конфигурация `wm size 960x720` дала viewport 720×960; форма и preview
   помещаются. Изменение размера пересоздаёт Activity и открывает Play; возврат
   через R/B восстанавливает форму. Автоматическое удержание текущего экрана при
   таком пересоздании не реализовано. Нативный размер восстановлен.
6. Apply → Y вернул порог 5 → R2 восстановил 8. Start сохранил и запустил игру.
7. В официальном runtime: начальное значение 2; два нажатия дают 6 без победы,
   третье — 8 и `WIN!`; сброс возвращает 2. Gameplay вводился ADB Z/X с удержанием.
   Select → «Завершить игру» вернул строку 21. Это техническое свидетельство,
   не новая приёмка физических кнопок владельцем.
8. Повторно открыта форма, знак сравнения переключён на `==`, preview соответствует;
   B отменил изменение. Финальная установка 0.0.40 восстановила тот же проект
   и форму `score>=8`. В ней нет неподтверждённой правки. Media остаётся muted.

В первом автоматизированном проходе команды после смены размера ошибочно попали
на Play и запустили старый тестовый `shared` с намеренным `WRONG TAB INCLUDED`.
Он завершён через меню; после наблюдения фактического экрана проверка повторена
на «Копии 10». Эта ошибка тестового маршрута не приписывается новому редактору.

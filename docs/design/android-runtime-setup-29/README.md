## Automated checks and remaining boundaries

All portable host suites, Android compilation and APK signature verification
passed. `RuntimeArchiveTest` has 37 synthetic/workflow checks; passing all three
user archive paths adds two explicit wrong-platform rejection checks (39 total).
Coverage includes names independent of filenames, missing/empty required entries,
ELF architecture/class/endianness/type, traversal and case collisions, damaged CRC,
truncated ZIP, compressed-size and entry-count bounds, bounded provider copy,
cancellation and preservation of the accepted candidate on replacement failure.

Inspection reads all ZIP entries with CRC/size checks, bounded at 64 MiB archive/
entry, 128 MiB total inflation and 512 entries. It identifies an ARM64 ELF header;
it does not certify publisher authenticity, full executable validity, version or
successful runtime execution. The filename is only a display label. No binary
is executed and no archive member is extracted by this slice.

The worker owns application context and survives Activity recreation; process
loss during an incomplete copy requires selecting the source again. Copies use
generated UUID names; an AtomicFile journal points to the accepted copy. Cleanup
only considers app-generated immediate files, and skips orphan pruning when the
previous journal cannot be read. Provider calls have no timeout yet. Disk-full,
provider-hang and abrupt-power-loss behavior need device fault tests before release.

Next: isolated extraction and environment preparation, activation with recovery,
then an official-runtime test launch. Automatic first-run routing, project/library
folder activation and real Splore synchronization remain separate required work.

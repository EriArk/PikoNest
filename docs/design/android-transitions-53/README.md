# Android lab 0.0.53 — M05.1: парный переход между областями

2026-10-04. Рабочий параметризуемый рецепт в общем редакторе Lua, часть будущего
инструмента механик. Это не завершённый редактор переходов, сцен или M05.

## Что получает пользователь

**Код → A → X → Переход · пара областей**. Форма задаёт две переменные точки,
отдельное имя памяти перехода, начало областей A/B и их общий размер в пикселях.
X/Y выбираются из имён проекта либо вводятся контроллером. Координаты/размеры
меняются стрелками или числовым вводом. Затем показывается полный Lua; A вставляет
его перед выбранной строкой, B отменяет, Start не применяет предложение.

Блок ставится в `_update` после изменения X/Y. Вход точки в A переносит её в начало
B, вход в B — в начало A. После переноса блокировка сохраняется, пока точка не
выйдет из обеих областей. Размер спрайта не участвует. Начальная точка внутри
области с ещё не заданной памятью (`nil`) переходит при первом вызове.

**L на любой строке известного блока** снова открывает поля. Все повторные
использования изменённого параметра заменяются вместе, с полным сравнением и
одной отменой. Неизменённые байты, отступы и окончания строк сохраняются.
Ручная неизвестная логика не заменяется обратно рецептом. Формат журнала не менялся.

## Проверка жанровой независимости

По вопросу владельца проверены фактические зависимости, а не только название:

- Запись находится в общем `LuaInsert.ITEMS`, доступном blank/imported cart.
  Здесь нет проверки template ID, жанра или `HeroBinding`/`MoonGardenBinding`.
- Переносимый `DoorTransition` не импортирует Android, спрайты, карту, камеру,
  физику или движение. Имена X/Y выбирает автор: это может быть курсор или фигура.
- Автор отдельно задаёт визуальное представление и изменение координат.
  Камера при необходимости читает уже изменённые X/Y обычным Lua.
- Интерфейс назван «пара областей». Двери/порталы — возможное применение,
  а не обязательные сущности модели. Внутренний ID `door_pair` сохраняется для
  восстановления предложения; это не игровой тип объекта или секция `.p8`.

Результат — обычный `do`/локальные переменные/сравнения/присваивания. Правила Lua
сверены с [официальным руководством PICO-8 0.2.7](https://www.lexaloffle.com/dl/docs/pico-8_manual.html).
Никакая библиотека PikoNest игре не нужна. Это инструмент с узкой операцией, а не
написанный только для демонстрационного cart фрагмент; общий каталог/связи M01
и удобное размещение механик без знания строки ещё не завершены.

В последних срезах есть перекос в пространственные механики. Поэтому следующий
приоритет — **M02.1: условия, счёт и состояния в игре без координат/движения**.
Проверка этого пути не должна сводиться к запуску готового шаблона.

## Границы

- Сейчас только пара равных непересекающихся прямоугольников и перенос точки
  к началу другой области. Левая/верхняя границы включены, правая/нижняя исключены.
- Нужны простые переменные X/Y; поля таблиц и произвольные выражения не поддержаны.
  Их начальные значения и место вызова задаёт автор. Статического анализа типов нет.
- Память должна иметь новое отдельное имя для пары/точки. Конфликты, API-имена,
  includes и изменённое окружение отклоняются до записи. Известный блок для
  проверки повторной правки временно исключается из анализируемого текста.
- Целые координаты формы −16384..16383, размеры 1..1024 удерживают суммы концов
  областей в диапазоне 16.16. Это ограничение формы PikoNest, не предел PICO-8.
- Другие независимые пары имеют отдельную память. Глобальное согласование
  пересекающихся пар/цепочек не реализовано; их порядок может давать каскад.
- Нет swept-проверки пересечения при скачке через область, AABB объекта, отдельной
  точки прибытия, одностороннего перехода, внешнего условия, анимации перехода,
  состояния сцен и загрузки multicart. Это остаётся M05. Пространственная механика
  не заменяет общие события/правила M02 и не становится обязательной для проектов.

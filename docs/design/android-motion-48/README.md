# Android 0.0.48 — движение с препятствиями карты

2026-10-04, база `736038f`. Ограниченный **M03.2b**: обычная Lua-функция
перемещает прямоугольник, проверяя путь по X, затем по Y. Настраиваются флаг
препятствий, размер поля и поведение за краем. Отдельная форма вставляет вызов
с переменными координат, размером объекта и выражениями шага. Герой и жанр
не заданы; функция пригодна для любого прямоугольного объекта.

## Путь пользователя

1. Код → A редактировать → X вставить → **«Движение · стены»**.
   Выбрать имя, флаг 0–7, размер карты в клетках и поведение за краем.
2. «Просмотреть Lua» → прочитать весь блок → A вставить в начало исходника.
   Одна отмена удаляет весь блок с двумя локальными вспомогательными функциями.
3. В теле `_update` выбрать **«Движение · вызов»**. Указать функцию, разные
   переменные X/Y, ширину/высоту объекта и шаги X/Y **в пикселях карты**.
   Переменные нужно заранее инициализировать обычным Lua/инструментом переменных.
4. Просмотреть вызов → A вставить → Start сохранить и проверить в PICO-8.
   Код отрисовки использует те же координаты; автоматической связи со спрайтом нет.

Поля меняются стрелками; выражения можно набрать экранной клавиатурой с контроллера.
В полях выражений X открывает существующий выбор имён/API; просмотр всего вызова
доступен последней кнопкой формы. В просмотре ↑↓ читают строки, ←→ или L/R листают,
B возвращает к полям. Start внутри предложения не применяет и не запускает его.
Предложение и позиция просмотра восстанавливаются после перезапуска.

## Обычный Lua и границы

`move_box(x,y,w,h,dx,dy)` возвращает `x,y,hit_x,hit_y`. Форма вызова присваивает
первые два результата выбранным переменным; флаги столкновения доступны в Lua.
Алгоритм проверяет всю полосу движения, затем при препятствии находит максимально
допустимый шаг двоичным поиском до точности PICO-8. Применяется сначала X, затем Y
из нового положения X: это последовательность двух осей, не прямая диагональ.
Свободная ось позволяет продолжать движение вдоль стены.

- Прямоугольник полуоткрытый, точное касание разрешено; прозрачные пиксели спрайта
  не влияют на коллизию. Препятствия определяются через `mget`/`fget`.
- Пустой размер оставляет координаты прежними и возвращает false/false.
- Уже застрявший в препятствии объект остаётся на месте с true/true:
  автоматического выталкивания пока нет.
- В режиме «Препятствие» граница поля — стена; «Свободно» допускает выход.
- Проверки диапазона вызывают обычный Lua `assert` при переполнении координат
  или полосы движения. Нечисловые аргументы дают обычную ошибку Lua.
- Числа 16.16, минимальная единица `0x0.0001`, `abs` и `sgn` сверены с
  [официальным руководством](https://www.lexaloffle.com/dl/docs/pico-8_manual.html).
  Переполнение не маскируется успешной проверкой PikoNest.

Перед вставкой проверяются имя функции/обоих помощников и переопределения API.
Форма вызова требует объявление функции с шестью именованными аргументами и
разные имена функции/X/Y. Это лексическая проверка, не доказательство доступности
функции/переменных во всех областях видимости или корректности ручного Lua.
Неподдержанные формы объявления могут быть введены общим редактором.

Не реализованы обратная форма всей вставленной механики/многострочного вызова,
автоматическая привязка к объектам и hooks, столкновения объектов друг с другом,
склоны, гравитация/прыжок и профилирование множества объектов. Поиск при столкновении
повторно читает клетки полосы; число итераций ограничено 31, но это не гарантия
бюджета для любой сцены. Карта использует обычную память PICO-8 до 128×64,
включая стандартную общую gfx/map-область; переназначение памяти не анализируется.
Длинные выражения ввода пока требуют набора: M01 ещё должен дать более удобный
выбор управления/связей. M01/M03 и полный авторский цикл не закрыты.

## Проверено

- Полный `build.ps1` прошёл, включая **33 новые проверки TileMotionTest**:
  вставка/конфликты, сохранность исходника, Undo/Redo, восстановление, отдельный
  вызов, контроллерный preview, блокировка Start, ошибка записи/повтор.
  Финальная повторная сборка меняла только короткие подписи интерфейса.
- Официальный пользовательский **PICO-8 0.2.7**, Retroid Pocket Classic Android 14:
  [проверочный картридж](runtime-check.p8) прошёл **22/22** ([экран](runtime-check.png)).
  Проверены обе стороны стены, пол/потолок, скольжение/угол, дроби/точное касание,
  минимальная единица/ширина, начальное пересечение, пустой размер, границы,
  нулевой шаг, внешнее начало/выход, независимость camera и смена флага.
  Assert-ветви недопустимых диапазонов отдельно в runtime не проверялись.
- Через UI создана **«Копия 15» (`remix-0015`)**. Флаг 7, поле 16×16, за краем
  препятствие. Force-stop восстановил предложение; Save → Undo → Redo побайтно
  вернули [исходную копию](baseline.p8) и вставленный блок соответственно.
- Через UI добавлены X/Y, `_update`, вызов с `btn()` и шагом 12, круг и вывод
  координат. [Итоговый cart](tested.p8) в официальном runtime показал
  **(16,40) → (24,40)**: остановку перед цветком, хотя шаг больше тайла.
  Затем движение вниз дало **(24,120)**, до края поля.
  [Начало](game-start.png), [у препятствия](game-wall-held.png),
  [после движения вниз](game-slide-held.png), [возврат в код](returned.png).
- **30 прежних файлов** проектов/библиотеки сохранены побайтно; добавлен один
  проект. Все секции кроме Lua в копии прежние. Вставленный блок движения
  побайтно совпадает с блоком проверочного cart.
  [Сверка](verification.json), [хеши](preservation.json).

Управление проверено событиями ADB, не физической пользовательской приёмкой.
Короткие down/up не удерживают `btn()` достаточно долго; для движения использован
`input keyevent --longpress`. Ошибка маршрута в локальном скрипте набора минуса
замечена в preview и исправлена до вставки/запуска; код приложения не менялся.
Родной экран 1240×1080 и компактный 720×960 просмотрены. Экран возвращён к родному
размеру, media volume **0**, в мастерской сохранённая копия без предложения.
Временный тест удалён из Games; его исходник сохранён здесь.

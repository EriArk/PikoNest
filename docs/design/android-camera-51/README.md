# Android lab 0.0.51 — N02.1: камера, границы и экранный интерфейс

2026-10-04. Ограниченный рабочий срез N02, не завершение камеры/сцен или M2.

## Путь пользователя

В любом проекте: **Код → A → X → Камера**. Герой и шаблон не требуются.

- **Положение:** X/Y левого верхнего угла видимой области в пикселях мира.
- **Следить:** X/Y точки мира, ширина/высота поля в клетках 8×8. Выражения
  выбираются из имён проекта через X либо набираются контроллером; числа меняются
  стрелками. Размеры также показаны в пикселях.
- **Экран:** `camera()` после мира, перед счётом/меню. Эти элементы используют
  экранные координаты и остаются неподвижными.

Все три действия сначала показывают прокручиваемый Lua и требуют A для вставки.
Start в предложении не сохраняет и не запускает игру. B возвращает к полям;
из полей можно отменить предложение. Сохранение/Test идут обычным путём редактора.

Для готового вызова: **L** на его строке. Точная известная формула follow открывает
четыре исходных поля; обычный `camera(x,y)` — два выражения; `camera()` — просмотр
сброса. Изменения видны в сравнении «Было / Будет», заменяются только выбранные
аргументы; пробелы/комментарии вокруг сохраняются. Одна отмена возвращает всю
правку. Повторное подтверждение без изменений не добавляет историю.

## Правила PICO-8 и границы инструмента

Сверены пользовательское руководство 0.2.7 и
[официальное руководство: camera / mid / max](https://www.lexaloffle.com/dl/docs/pico-8_manual.html).
`camera(x,y)` сдвигает рисование на `-x,-y`; `camera()` сбрасывает сдвиг.
Обычное применение:

```lua
function _draw()
 cls(1)
 camera(mid(64,(x),max(64,32*8-64))-64,mid(64,(y),max(64,32*8-64))-64)
 -- map / spr / другие объекты в координатах мира
 camera()
 print("score",4,4,7)
end
```

Поле начинается в (0,0), камера ограничена диапазоном от 0 до размера поля минус
128. Если поле меньше экрана, соответствующая ось остаётся в 0. Точка сначала
ограничивается, затем вычитается 64: крайнее отрицательное число PICO-8 не должно
переполниться при вычитании и перенести камеру к противоположному краю. Выражение
каждой координаты вычисляется один раз. Камера PICO-8 переводит дробный сдвиг в
целый; проверено 64.75/80.5 → 0/16 в официальном runtime.

Размеры формы — 1..128 × 1..64 клетки, как стандартная карта. Это границы данного
инструмента, **не предел размеров миров PICO-8**. Произвольные начала/границы,
большие виртуальные миры и переназначенная память ещё не имеют такой формы.

Нет автоматического поиска `_draw`, объекта или места для HUD. Пользователь
явно выбирает строку и порядок рисования. Вставка не оборачивает чужой код и не
перестраивает сцену. `camera()` восстанавливает начало экранных координат, а не
сохранённую произвольную родительскую камеру; вложенные слои требуют отдельного
save/restore. Смена положения камеры не меняет координаты объектов/коллизий.

Переопределения `camera`, а для follow ещё `mid`/`max`, includes и изменённое
окружение дают отказ до записи. Это консервативная лексическая проверка,
не полный анализ Lua. Выражения проверяются на выход из границ аргумента;
синтаксис/типы и фактическую доступность переменных проверяет официальный runtime.
Изменённые вручную формулы остаются обычными X/Y-выражениями, если безопасно
распознаётся сам вызов. Неизвестные формы не нормализуются.

Плавное следование, комнаты, события перехода, параллакс, визуальное размещение
диапазона рисования и автоматические связи с объектами **ещё не реализованы**.

- Полная сборка прошла. **69 новых проверок WorldCameraTest**: вставка, LF/CRLF/CR,
  повторная правка, отображение полей в правильные аргументы, пробелы/комментарии,
  no-op, отмена/повтор, восстановление preview, конфликт API, границы выражений,
  имена проекта, контроллерный путь, ошибка записи/повтор и неизвестные секции.
- [Проверочный картридж](runtime-check.p8) в пользовательском **PICO-8 0.2.7**
  прошёл **13/13**: центр/края, маленькое поле, 16.16-экстремумы, дроби, вычисление
  цели один раз, world→screen, неподвижный HUD и reset ([экран](runtime-check.png)).
- Через контроллерные события ADB создана **«Копия 18» (`remix-0018`)** из копии 17.
  В самой копии общим редактором введён короткий пример поля 256×256 без героя;
  камера follow и reset добавлены новыми формами. Крестовина меняет точку обзора.
  [Исходная копия](baseline.p8), [готовый пример](tested.p8).
- Force-stop восстановил предложение; Start не применил его. Save → Undo → Redo
  побайтно восстановили исходную копию и новый пример. Повторное открытие L,
  изменение размеров 32→24, сравнение, сохранение и отмена вернули точный исходник.
  В [изменённом варианте](edited.p8) отличаются только два размера.

Во время разработки исправлены два тестовых допущения: тест анимации считал её
последним пунктом каталога; отказ для `x,y` ожидал полного синтаксического анализа,
хотя скобки уже не дают выйти из аргумента. Финальная сборка прошла после этих
правок; заключительная пересборка меняла только подписи/показ размеров.

При смене разрешения Activity вернула приложение на Play; черновик восстановился
после входа в проект. Локальный сценарий сначала продолжил отправку кнопок на Play
и открыл системный выбор папки, где DocumentsUI завис. Выбор отменён, папки не
менялись; после закрытия системного окна выполнен правильный путь к черновику.
Известный R03-разрыв после внешнего теста также проявился: Test был заблокирован
старым `dispatched` до возвращения в LaunchActivity. Новая камера его не закрывает.

Родной экран 1240×1080 и компактный 720×960 просмотрены. Размер возвращён к родному,
media volume **0**, оставлена сохранённая копия без предложения. Управление через
ADB не заменяет физическую пользовательскую приёмку. Runtime Test 8 не менялся.

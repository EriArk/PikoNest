# Android 0.0.46 — проверка точки карты по флагу

Обновление 0.0.47: отложенные 21 runtime-проверка выполнены через обычный запуск
PikoNest. [Результат](../android-area-47/README.md). Ниже сохранён журнал среза 0.0.46.

2026-10-04, база `5d7f66c`. Ограниченный первый рецепт M01.1 / M03.1.
Работает в blank/imported/template через общий каталог Lua, без обязательного героя.
Это возвращающая boolean функция, а не автоматическая физика или готовое движение.

## Путь пользователя

Код → A редактировать → X вставить → «Препятствие · точка карты».
Пять полей: имя функции, флаг 0–7, ширина/высота игрового поля в клетках,
поведение за краем («Препятствие» / «Свободно»). Числа меняются стрелками;
только собственное имя при необходимости требует контроллерного набора.
Два видимых поля прокручиваются крестовиной; весь короткий Lua остаётся виден.

«Вставить в черновик» добавляет функцию **в начало Lua**, даже если курсор внутри
`_draw`. Это явно указано над формой. Исходные строки не заменяются. До применения
Start не сохраняет/не запускает предложение. B отменяет форму. Предложение и его
параметры восстанавливаются после перезапуска. Одна отмена убирает всю вставку;
после сохранения доступна общая история проекта. Ошибка записи оставляет черновик.

Вызов `solid_at(x,y)` даёт `true`, если точка относится к тайлу с выбранным флагом.
`x/y` — пиксели относительно начала карты (0,0), независимо от экранной камеры.
Функция округляет координаты вниз до клетки 8×8; за выбранными границами возвращает
явное настроенное значение. Размер по умолчанию 128×32; инструмент допускает
ширину 1–128 и высоту 1–64. Это пределы первого рецепта обычной карты, не пределы
всех режимов памяти PICO-8. Переназначение map memory этим инструментом не анализируется.

Обычный Lua остаётся редактируемым. Вызов пока вводится как выражение в существующем
поле, например `print(solid_at(32,40),16,60,7)`, либо в условии. Отдельного выбора
функции с аргументами и повторного открытия всей механики как формы пока нет.
Параметры формы можно изменить до вставки; после неё — обычный Lua/Undo.
Нет скрытой подписки на update/draw или дополнительного runtime-компонента.

Сверены [MGET, FGET и FLR официального руководства](https://www.lexaloffle.com/dl/docs/pico-8_manual.html).
MGET читает номер тайла, FGET с индексом — boolean бита, FLR округляет вниз.
Тайл 0 тоже имеет флаги; его невидимость в обычном `map` не означает отсутствия
флагов. Проверка одной точки не заменяет проверку площади/пути движущегося объекта.

## Защита исходника и границы

Переносимый `TileProbe` генерирует обычную функцию, `LuaDraft` вставляет её одной
правкой. Все прочие секции сохраняются побайтно. Строки/комментарии исключаются
из консервативной проверки имени; любое другое употребление выбранного имени
считается конфликтом. Известные имена API/стандартной библиотеки/колбэков запрещены.
Переопределения flr/mget/fget, includes и явное изменение `_ENV`/`_G` отклоняются
до вставки. Это ограничение проверки PikoNest, не запрет этих возможностей в PICO-8.
Полного анализа областей видимости и косвенных динамических изменений окружения
нет; сам результат остаётся доступен для просмотра и проверки в официальном runtime.

## Свидетельства

- Полный `build.ps1` прошёл, включая новый `TileProbeTest`: **69** проверок.
  Покрыты top-level размещение из тела draw, сохранение исходного Lua/CRLF/ресурсов,
  конфликты, диапазоны/выбор полей, восстановление, Cancel, единая отмена/Redo,
  Start в форме, ошибка сохранения и повтор. Ядро компилируется без Android.
- На Retroid Pocket Classic / Android 14 создана через UI **«Копия 13»**
  (`remix-0013`) из проекта предыдущего среза. Выбраны флаг **7**, поле **16×16**,
  за краем **«Свободно»**. Force-stop восстановил форму. Save/Undo/Redo проверены
  побайтно на первой сборке. Данные прежних проектов не менялись.
- Обнаруженное обрезание двух строк compact-preview исправлено сокращением имён
  локальных параметров. После второй сборки повторно проверен только этот экран;
  прежний вариант функции удалён и новый вставлен через обычный редактор.
  [Итоговый helper](helper-final.p8) содержит новую компактную запись.
- Через поля существующих `print` введены два вызова. Официальный пользовательский
  PICO-8 0.2.7 показал **true** для цветка в (32,40), **false** для травы в (16,24).
  Select → выход вернул в мастерскую. [Проект](tested.p8), [скриншот](game.png).
- Дополнительная [headless-проба краёв](runtime-probe.p8) подготовлена, но **не
  выполнена**: отдельный proot-процесс остановился до PICO-8. После одной правки
  временного пути осталась ошибка execve busybox; [лог](runtime-probe.txt).
  Это не ошибка, полученная от картриджа. Её результаты не считаются проверенными;
  отрицательные/дробные координаты, край, tile 0 и влияние camera остаются для
  отдельной runtime-проверки. Не повторяли рабочий UI-сценарий ради этого стенда.
- Все **28** прежних файлов проектов/библиотеки сохранены; добавлен один проект.
  [Хеши](preservation.json), [сверка](verification.json), [исходник](baseline.p8).
  Gfx/map/gff в новом проекте не менялись. Экран возвращён к родному размеру,
  звук остаётся на 0. Физическая эргономика проверками ADB не подтверждена.

# Android 0.0.14 — картридж с собой

Проверено 2026-10-03 на Retroid Pocket Classic, serial `MC94516AQF040305380`.
Это экспорт одного сохранённого `.p8` в выбранный внешний файл.

## Сценарий

На полке выбрать картридж → Y, либо «Сохранить .p8» → предпросмотр → A →
выбрать место в Android → записать → прочитать файл обратно и сравнить байты →
подтверждение. B на предпросмотре закрывает его. B в системном окне возвращает
к предпросмотру. Start и другие действия не запускают игру из этого сценария.
После успеха A/B возвращают на полку без новой записи.

Берётся сохранённая версия выбранного проекта на момент открытия предпросмотра,
а не активный проект, миниатюра или неподтверждённый черновик. Последующие изменения
источника не меняют уже показанную копию. Код, графика, звук, неизвестные секции и
окончания строк переносятся без нормализации. Имя предложено заранее, имя/папка
выбираются через системный диалог. Кириллица и пробелы проверены на устройстве.

Экспорт не переносит соседние файлы, includes, другие части multicart, историю
или записи библиотеки. Он не проверяет Lua и не очищает персональные привязки
картриджа. Это не Share Clean Cartridge или резервная копия всей мастерской.
Бюджет снимка 2 МиБ — ограничение стенда, не ограничение PICO-8.

## Сохранность и восстановление

Portable `CartridgeExport` содержит независимые байты и состояние
PREVIEW/WRITING/SAVED/UNCERTAIN. Журнал PKE1 — метаданные интерфейса, не формат игры.
`LibrarySession` управляет действиями, а Android-адаптер использует
[ACTION_CREATE_DOCUMENT](https://developer.android.com/training/data-storage/shared/documents-files).
Новая запись не меняет проект внутри мастерской и не открывает импортированный
исходный URI на запись. После закрытия выходного потока файл открывается заново
для побайтового сравнения. Только затем появляется зелёное подтверждение.

Запись/проверка идут в рабочем потоке. При пересоздании Activity незавершённая
задача удерживается и получает нового слушателя; второй поток не читает её
AtomicFile параллельно записи. Завершённый результат сохраняется в журнале.
После смерти процесса WRITING означает неизвестный результат: приложение не
запускает запись заново и не объявляет успех. Ошибка записи или проверки тоже
показывает неопределённый результат: в папке мог остаться неполный файл. A явно
открывает выбор нового места, B закрывает; удалений и автоматических перезаписей нет.
Предпросмотр и уже проверенный результат переживают смерть процесса.

Обычные `.p8` и внешние зависимости описаны в
[руководстве PICO-8](https://www.lexaloffle.com/dl/docs/pico-8_manual.html).
Сообщение об успешном сохранении файла не означает, что игра проверена в runtime.

## Границы проверки

Внутри мастерской действия проверены через ADB-кнопки. В системном Android-окне
Save и выбор файла для обратного импорта нажаты касанием. Клавиатура не потребовалась.
Это не физическая приёмка контроллера или доказательство полного пути без касаний.
Cloud providers, фактический обрыв записи и поворот Activity посреди медленной
записи на устройстве не проверялись; ошибки потоков и портов покрыты core tests,
восстановление WRITING проверено отдельно симуляцией журнала.

Постоянные папки проектов/библиотеки, визард, перенос зависимостей и `.p8.png`
остаются отдельными задачами. Выгрузка обычного `.p8` не заменяет эти сценарии.

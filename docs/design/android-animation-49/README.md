# Android 0.0.49 — кадры анимации

2026-10-04, база `ff8a0d9`. Первый ограниченный **N01.1**: визуальный выбор
областей спрайт-листа, порядок и длительность кадров, Play/Pause/Stop, повтор,
позиция и явная вставка обычного Lua. Инструмент доступен из общего редактора
в любом проекте; герой, шаблон и отдельный движок анимаций не требуются.

## Путь и управление

Код → A редактировать → поставить курсор внутри `_draw` после `cls()` → X вставить
→ **«Анимация · кадры»**. Первым кадром становится текущая область листа.

- ↑↓ выбирают поле, ←→ меняют его значение. L/R выбирают соседний кадр и
  останавливают просмотр на его начале. Выбор редактируемого кадра и позиция
  воспроизведения показаны отдельно: рамка миниатюры и надпись «Пауза/Играет N».
- «Область» → два угла на листе. Крестовина перемещает угол, X переключает шаг
  8/1 пиксель, A подтверждает. Можно выбрать прямоугольник любого размера,
  помещающийся в обычном листе 128×128, включая нижнюю общую с картой половину.
- «Длительность» меняется на 50 мс. «Копия кадра» добавляет ссылку на ту же область
  с тем же временем: пиксели листа не копируются и не переписываются.
- «Порядок» + ←→ переставляют выбранный кадр вместе с длительностью.
  Удалить последний оставшийся кадр нельзя. Все эти действия пока внутри предложения.
- X запускает/приостанавливает просмотр; Y останавливает на первом кадре.
  Можно выбрать повтор по кругу или один проход с удержанием последнего кадра.
- «Место» задаёт общие X/Y для отрисовки. Это положение использования ресурса,
  не новая сущность игры. Вставленный код можно изменить, например передать `x,y`.
- «Просмотреть Lua» показывает весь блок с прокруткой ↑↓ и страницами ←→/L/R.
  A вставляет перед строкой курсора одной отменяемой правкой. B возвращает к кадрам.
  Start внутри предложения ничего не вставляет и не запускает.

B на основном экране отменяет предложение целиком, исходник остаётся прежним.
Состояние кадров, незавершённый выбор области, позиция и просмотр Lua сохраняются.
После восстановления воспроизведение остановлено на сохранённой позиции.
Touch выбирает миниатюры, поля/действия и точки листа; полный путь доступен с контроллера.

## Семантика и границы среза

Игра получает `do ... end` с локальной таблицей областей/времени и обычным `sspr`.
Время берётся из `time()` **от запуска картриджа**. Счётчик кадров отрисовки и
дополнительный `_update` не создаются. При loop берётся остаток по длительности
последовательности; без loop после последней границы удерживается последний кадр.
Новый кадр начинается на своей границе времени, а не после неё.

Кумулятивные границы времени записаны точными 16.16 hex-литералами в секундах;
миллисекунды округляются вниз с погрешностью меньше `1/65536` секунды. Так нет
переполнения `time()*fps` или большого целого числа миллисекунд. Размеры и
координаты кадров передаются `sspr` в пикселях. Сверены
[SSPR, TIME и числовой формат официального руководства](https://www.lexaloffle.com/dl/docs/pico-8_manual.html).

Просмотр показывает исходные цвета, прозрачный 0 и общий масштаб/начало координат
для всех кадров: разные размеры не вызывают ложное увеличение/уменьшение.
Он не исполняет Lua игры, её `pal/palt/camera/clip`, переназначение памяти или
динамическую правку листа. Часы просмотра — время интерфейса; часы игры — время
PICO-8. Preview не заменяет Test, особенно при паузах/нагрузке игры.

Текущие ограничения **PikoNest**, не PICO-8: до 32 кадров в предложении, время
50–5000 мс с шагом 50, позиция от -127 до 127. Общий лист остаётся 128×128;
редактор не расширяет память спрайтов. Каждая вставка создаёт независимый локальный
блок, но таблица сейчас строится при каждом выполнении блока — нагрузка многих
анимаций ещё не профилировалась. Переопределённые `time/sspr`, includes и изменённое
окружение дают понятный отказ до записи; лексическая проверка консервативна.

**Ещё нет:** повторного открытия вставленного блока визуальной формой, отражения,
событий запуска/сброса, переходов между последовательностями, привязки к состоянию
движущегося объекта и сохранения анимации в библиотеку. После вставки пока доступен
общий Lua-редактор; чужой код инструмент не пытается распознать или переписать.
Поэтому N01 и M2 остаются частичными.

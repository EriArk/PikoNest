# Android 0.0.42 — свой спрайт в игре

2026-10-04, база `d0500c6`. Ограниченный G04.1: обычный `sspr` соединяет
собственную графику с draw-кодом в любом проекте, включая blank без героя.
G04/M1/M2 и физическая пользовательская приёмка целиком не закрыты.

## Путь

В коде выбрать строку внутри `_draw`, после `cls`, перед которой нужен вызов.
X → «Спрайт · разместить» (последний пункт каталога):

1. Первый угол области на листе 128×128; начальная область — выбор редактора спрайтов.
2. Второй угол; доступны прямоугольные области, в том числе больше 16×16.
3. Положение на экране 128×128. Крестовина перемещает, X или L/R меняет шаг 8/1.
4. Предпросмотр кода и явное «Вставить в черновик». До этого исходник не меняется.

A продолжает, B возвращается на предыдущий шаг и отменяет с первого.
Касание также задаёт угол/положение. Start во время предложения не применяет
правку и не запускает игру. После вставки Y/R2 отменяют/возвращают её целиком,
Start сохраняет и тестирует. Каждое использование независимо; лист не копируется.
Обычные шестипараметрические `sspr(...)` затем доступны через L → поля строки.

## PICO-8 и переносимость

Семантика сверена с [официальным руководством, SSPR](https://www.lexaloffle.com/dl/docs/pico-8_manual.html#SSPR):
координаты и размеры заданы в пикселях; при отсутствии DW/DH размеры назначения
совпадают с источником. Цвет 0 прозрачен по умолчанию. Прямоугольник может иметь
произвольные размеры внутри листа, а не только 8×8/16×16.

`SpritePlacement` и восстановление находятся в portable core. На диск попадают
только обычный Lua и стандартные ресурсы; вспомогательный объект размещения
нужен редактору лишь до применения. Формат журнала 6 добавлен без изменения
чтения старых форматов 1–5; существующие вставки и позиции enum не переставлены.
Операция использует прежний byte-preserving Lua draft, проверку конфликта и save.

## Проверки

- Полная сборка и существующие regression-тесты прошли, включая 40 новых
  проверок: CRLF/отступы, сохранность ресурсов/неизвестных секций, все четыре
  стадии восстановления, отмена/повтор, обратные углы, произвольный прямоугольник,
  нижняя половина листа, clipping, touch, защита от обхода подтверждения.
- На Retroid через контроллерные события ADB создан **«Чистый лист 5»**,
  `blank-0005`; сердечко нарисовано кистью через тот же ввод. Lua не подменялся
  скриптом или разработчиком. [Графика до размещения](drawn.p8).
- Выбрана область 24×24, размещение 24,40; после force-stop предложение
  восстановлено. До Apply cart совпал с нарисованным побайтно.
- Apply → Undo → Redo; второе использование того же источника в 80,72 → Test.
  [Обычный итоговый cart](two-hearts.p8) запущен официальным PICO-8 0.2.7.
  Все **16384** центров пикселей игрового экрана совпали с ожидаемыми цветами:
  [проверка](runtime-pixels.json). Это конкретная проверка двух вызовов,
  не обещание полного воспроизведения draw-state любого проекта.
- Проверены native 1240×1080 и compact 720×960, возврат из игры, Cancel новой
  вставки и Cancel поля существующего вызова. На compact поля X/Y различимы,
  длинный preview переносится по запятой. Touch проверен отдельно с отменой.
- Все **24** прежних файла проектов/библиотеки сохранены; добавлен один cart.
  [Хеши до/после](preservation.json). Gfx нового cart до/после вставок идентичен.
- Размер экрана восстановлен, media volume 0. Физический контроллер в этом
  прогоне пользователь не проверял; ADB не заменяет физическую UX-приёмку.

Preview показывает только выбранную область с обычной палитрой и прозрачным 0,
без выполнения Lua, camera, pal, palt или fillp. Итог проверяется через Test.
Выбор места вставки пока ручной: инструмент не ищет автоматически тело `_draw`,
не переставляет чужой код и не создаёт callback за пользователя. Порядок рисования
равен порядку вызовов Lua. Визуальное повторное открытие уже вставленного вызова,
масштаб/отражение и выделение сразу нескольких использований пока не добавлены;
исходник и поля шести аргументов доступны. Диапазон положения в этом UI −127…127 —
граница первого preview, не ограничение координат PICO-8. Нижняя половина листа
доступна для чтения с пометкой общей памяти; вставка кода её не изменяет.

Undo/повторное открытие и явное использование через обычный `map()`.

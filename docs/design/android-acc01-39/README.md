# ACC-01 — от пустого картриджа до независимого запуска

2026-10-04, база `933dba4a3db5c15e8c0859b18a068a515f7428ab`, main.
Авторский путь выполнен на host 0.0.38 / Runtime Test 7. В 0.0.39 исправлена
устаревшая подсказка создания blank: вместо «код — просмотр» теперь
«Свой код, спрайты и правила игры». После обновления повторены открытие проекта,
Test и возврат. **Это техническое свидетельство ACC-01, не закрытие M1 или
приёмка владельцем.**

## Условия и границы ввода

- Retroid Pocket Classic, Android 14, `MC94516AQF040305380`, 1240×1080 landscape,
  density 320. Пользовательский официальный PICO-8 0.2.7 Raspberry Pi / ARM64.
- Создание и все правки игры — только видимый UI: ADB-инъекция D-pad, A/B/X/Y,
  L/R/L2/R2, Select, Start. Каталог вставок и палитра символов; без `input text`,
  вставки готового Lua в файл, замены blank или подключения внешней клавиатуры.
  Локальный helper отправлял только последовательности кнопок и снимал экран.
- Gameplay проверялся ADB keyboard Z/X с удержанием для `btnp(4/5)`.
  Это не доказательство физической эргономики геймпада. Работавшие у владельца
  кнопки не объявляются сломанными из-за ограничений инъекции ADB.
- В Android DocumentsUI экспорт завершён **одним касанием Save**: попытка
  D-pad-навигации перемещала выделение по списку, но надёжный переход на Save
  в этом прогоне не получен. Controller-only экспорт не засчитан.
- Независимый запуск — явный VIEW экспортированного файла в исходном
  `io.wip.pico8`, без обращения к host/provider PIKOOS. Для завершения этой
  внешней проверки использован Ctrl+Q. Само создание игры не использовало
  терминал для написания исходника; shell здесь — средство инъекции/наблюдения.
- Media mute сохранён. Звук и другие размеры экрана в этом срезе не проверялись.

## Пройденный путь

1. Play → R «Мастерская» → «Новая игра» → «Чистый лист». Создан `blank-0004`,
   автоматически названный «Чистый лист 4». Имя, герой и жанр не запрашивались.
   Исходный cart содержит только комментарий и `_draw` с `cls(1)`.
2. Во вкладке «Код» каталогом добавлены `_init`, `score=0`, `_update`,
   `if btnp(4)` с `score+=1`, `if btnp(5)` с `_init()`. В существующем `_draw`
   добавлены `print(score,16,60,7)`, круг, `if score>=3` и надпись `win!`.
   Выражение условия и надпись введены палитрой символов с контроллерных событий.
   Это набор обычных конструкций, не готовый игровой шаблон.
3. Start сохранил и запустил игру. Наблюдались 0 → 3 → `WIN!`, затем сброс к 0.
   Select → «Завершить игру» вернул вкладку «Код», строку 23.
4. В строке 21 выделена цифра 3 и заменена на 5 палитрой символов. Y вернул 3,
   R2 восстановил 5. После Test при счёте 3 победы нет, при 5 появляется `WIN!`.
   Возврат сохраняет выбранную строку 21.
5. В `cls(1)` намеренно удалена закрывающая скобка. L2 → подтвердить проверку
   копии: официальный runtime сообщил `unclosed (` на строке 18. A перевёл
   к этой строке. Undo восстановил скобку. Повторная проба не получила ошибок
   за отведённые четыре секунды; UI не назвал это проверкой всей игры.
6. Правка сохранена, host закрыт через Home/force-stop и открыт заново.
   Play → R → B вернул тот же проект/код, строку 18. После этого форма L
   существующего `circfill` изменила радиус на `score+3`; выражение введено
   экранной палитрой. Сохранён обычный Lua, состояние влияет на размер круга.
7. Меню → проекты → Y → предпросмотр → Android Save. Создан
   `/sdcard/Download/Чистый лист 4.p8`. Приложение прочитало файл обратно и
   подтвердило совпадение. Отдельное побайтовое сравнение с проектом тоже прошло.
8. Экспорт открыт через `io.wip.pico8/com.godot.game.GodotAppLauncher`,
   ACTION_VIEW/file URI. Официальный `pico8_64` работал под UID исходной оболочки
   `u0_a126`, вне приложения PIKOOS. Наблюдались 0 → 5, увеличение круга,
   `WIN!`, сброс к 0. Metadata, библиотека и исходный проект не передавались.
9. Установлена локальная 0.0.39 поверх существующего host. Исправленная подсказка
   проверена на устройстве без создания лишнего проекта. Тот же cart снова
   запущен через Test; меню вернуло редактор на строку 20.

## Выявленные UX-долги и следующая работа

- **C02.3:** условие `if` и простые присваивания пока правятся посимвольно.
  Для изменения одной цифры нужны меню начала строки/выделения и палитра.
  Следующий срез — поля для безопасно распознанных условий/присваиваний,
  preview, одна отмена, сохранение отступов/комментариев; неизвестный Lua
  остаётся в обычном редакторе. Без перегенерации тела блока.
- **Q02.1 / P02:** отдельно пройти фокус и подтверждение системного Save.
  Текущий результат не доказывает физическую неисправность кнопок и не даёт
  права закрыть экспорт с контроллера. Предусмотреть удобный повторный экспорт
  в уже разрешённое место без обязательного касания и без неявной перезаписи.
- **H01/H02:** разработчик знает, какие callbacks и строки вставить. Этот прогон
  не доказывает, что новичок сам найдёт нужный путь. Нужен короткий необязательный
  рецепт внутри мастерской с объяснением реального Lua, а не подмена blank игрой.
- Затем G04/G03 и M2: собственный ресурс в игре, карта/поле, анимация, камера.

Физическая приёмка и одобрение владельца отложены. ACC-01 остаётся открытым;
технический проход не означает готовности полного набора инструментов.

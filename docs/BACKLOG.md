# PIKOOS — задачи полного цикла

Версия плана: 2026-10-03. Основание: [аудит](STATUS.md), [этапы](ROADMAP.md),
[сценарии приёмки](ACCEPTANCE.md). ID ниже локальные, GitHub issues пока нет.

**Статусы:** «Частично» — переиспользовать существующую реализацию, закрыть указанный
разрыв; «План» — общего инструмента ещё нет; «Исследование» — сначала проверить
возможность/выбрать способ; «Позже» — вне обязательного локального Android-выпуска.
Ни одна задача ниже пока не закрыта целиком. Начатая проверка не равна «В работе»:
при фактическом старте записать commit/ветку, текущий срез и следующее действие.

Зависимости обозначают минимальные нужные контракты, а не требование отложить
любую черновую работу до полного закрытия всех крупных задач. Частичный срез
записывать явно, не закрывать всю строку. Нет зависимостей — «—». Все задачи A–Q
обязательны для заявленного полного локального продукта; X — отдельное будущее.
Критерий каждой строки дополняется общими требованиями сохранности/контроллера/
совместимости из ROADMAP. Перед реализацией сверить релевантный раздел официального
мануала и целевую версию, а не переносить ограничение прототипа в модель PICO-8.

## Как брать задачу

Выбрать конкретную строку и пользовательский срез, проверить зависимости и границы
мануала, реализовать путь целиком, приложить релевантные проверки и обновить статус.
Большая строка может получить подзадачи `C01.1` и т. п. с сохранением родительского ID.
Документация, UI, сохранение и Test не расходятся на независимые «готово» без
интеграции. Не закрывать родителя по одному успешному happy path.

Предлагаемый следующий срез: A01/A02 → C01 → C02/начальная C03/H01/H02 → ACC-01.
Это приоритет выполнения, а не назначение дат или обещание завершить весь каталог
одним заходом. Обнаруженный data-loss/runtime blocker получает явный приоритет
с объяснением влияния на этот путь.

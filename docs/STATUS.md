# Состояние PIKOOS

Аудит 2026-10-03, код `f98e27a`: Android lab 0.0.30 / Runtime Test 4.
Это сверка документации, исходников и сохранённых проверок. Новые проверки на
устройстве в рамках пересборки плана не выполнялись. Ранее полученные результаты
не означают приёмку всего продукта. Готового полного цикла создания игры ещё нет.

Обновление после аудита: lab **0.0.31** добавляет первый общий редактор Lua
с контроллерным набором, черновиком, выделением/буфером и отменой. В этом срезе
выполнены новые проверки на Retroid: ввод → восстановление → сохранение →
официальный runtime → исправление ошибки. [Свидетельства и ограничения](design/android-code-31/README.md).

Lab **0.0.32** продолжает C02.1: 17 вставок Lua/API, параметры и preview, одна отмена,
восстановление незавершённой формы. Из пустого проекта через UI собрана игра
«дойти до пяти»: ввод, состояние, условие цели и сброс проверены в официальном runtime.
[Новые свидетельства](design/android-insert-32/README.md). Это не закрывает C02/C03,
полную приёмку M1 или физическую эргономику контроллера.

Lab **0.0.33** добавляет C03.1: выбор общих имён текущего черновика и восьми выражений
PICO-8 в параметрах вставки. Локальные имена консервативно исключены, полного
разбора областей видимости нет. Через UI связаны `score` и радиус круга, добавлен
вывод `time()`; официальный runtime показал результат. [Свидетельства](design/android-symbols-33/README.md).

Lab **0.0.34** добавляет ограниченный C02.2: формы существующих вызовов, preview
«было/будет» и замена только изменённых аргументов. Радиус и цвет ранее созданного
круга изменены через UI, проверены в официальном runtime; остальные байты cart
сохранены. [Свидетельства](design/android-parameters-34/README.md).

## Как читать статус

- **Работает в ограниченном сценарии** — есть код и указанное свидетельство проверки.
- **Частично** — часть пользовательского пути есть, другие обязательные шаги отсутствуют.
- **Не реализовано** — требование/дизайн существует, рабочего общего инструмента нет.
- **Исследование** — даже способ реализации ещё нужно доказать.
- **Принято владельцем** — только явно одобренное направление или проверенный им результат.

Не складываем количество тестов, коммитов и экранов в процент готовности.
Каждая будущая задача закрывается по [правилам приёмки](ACCEPTANCE.md).

## Критические разрывы полного цикла

1. Первый буквальный редактор C01.1 уже позволяет менять обычный Lua в пустом
   проекте. C02.1 добавляет ввод, состояние и цель через каталог; C03.1 даёт общие имена, но навигация/области видимости ещё нужны; полноценный
   путь M1 ещё не принят. Напечатанная строка не считается созданной игрой.
2. Нарисовать спрайт не означает использовать его в игре. Подключение отрисовки,
   событий и поведения требует явного редактируемого кода/известной привязки: G04, M01.
3. Нет инструментов карты, анимации, звука и музыки. Сохранение этих секций
   парсером не считается их редактированием.
4. Запуск связан с подготовленной тестовой оболочкой. Выбор ZIP и удачная проба
   не завершают установку, настройку папок и Splore: R01–R08, P02.
5. Внутреннее атомарное сохранение и разовый экспорт не заменяют постоянную
   историю, внешний проект, резервную копию и полный перенос зависимостей.

## GitHub и границы аудита

Проверен приватный репозиторий [EriArk/pikoos](https://github.com/EriArk/pikoos),
ветка `main`. Issues включены; запросы открытых и закрытых issues/PR вернули пустые
списки, milestones также отсутствуют. Следовательно, отдельного трекера задач,
который мог бы дополнить документацию, сейчас нет.

[BACKLOG.md](BACKLOG.md) вводит стабильные локальные ID и проверяемые задачи.
Это **не номера GitHub issues**. При переносе задачи в GitHub сохранить ID в
названии и добавить ссылку сюда, не вести два независимых статуса.

Основания аудита: AGENTS, все тематические документы в `docs/`, текущий host README,
контракты runtime/parser, проектное хранилище, состав core/тестов и связанные
материалы `docs/design/`. Старый роадмап сохранён в [истории](ROADMAP_HISTORY.md).
Официальный [мануал 0.2.7](https://www.lexaloffle.com/dl/docs/pico-8_manual.html)
проверен как исходная карта инструментов/API; это не повторная runtime-проверка
всех описанных возможностей.

## Принятые ограничения планирования

Android сейчас; Linux позже. Обычный `.p8` и официальный runtime остаются основой.
Герой, жанр и шаблон не ограничивают доступ к общим инструментам. Принятая
пиксельная стилистика сохраняется; одобрение её основы не означает приёмку всех
новых экранов. GitHub APK release/prerelease возможен только после явного
подтверждения владельца, что результат полностью устраивает, и разрешения выпуска.

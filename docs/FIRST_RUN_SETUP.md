# Первый запуск: папки и официальный PICO-8

Статус: требования владельца и предлагаемый сценарий. Полный мастер ещё не реализован.
Работающий эксперимент использует отдельный Android-wrapper; это доказательство
запуска, но не готовая автоматическая установка внутри PikoNest.

Срез **0.0.30 / Runtime Test 4** расширяет подключение: **Папки → R PICO-8**.
A выбирает ZIP через Android, а после проверки готовит отдельный пробный запуск.
X выбирает другой ZIP, Y перепроверяет сохранённую копию, B возвращает
назад или отменяет выполняемую проверку. На экране указано, что нужен архив
**Raspberry Pi** из покупки; имя файла не служит доказательством совместимости.
Успешный результат называется «Архив проверен», а не «PICO-8 готов».

Переносимое ядро проверяет ZIP, обязательные `pico-8/pico8_64`, `pico8.dat` и
`readme_raspi.txt`, заголовок ELF64 little-endian AArch64, фактические длины и CRC
всех файлов. Отклоняет неоднозначные/опасные пути и повторяющиеся имена, включая
различающиеся только регистром. Ограничения эксперимента: 64 МиБ ZIP/один файл,
128 МиБ суммарной распаковки для проверки, 512 записей. Проверка ZIP сама по себе
ничего не запускает и не заменяет рабочую установку.

По отдельному действию A переносимое ядро готовит пакет с `pico8_64`, `pico8.dat`
и нашим обычным тестовым `.p8`. Runtime Test 4 принимает его через защищённый
одинаковой подписью вход, проверяет размеры/хеши и создаёт частную папку пробы.
Два файла PICO-8 подключаются к уже подготовленной среде только на время этого
запуска; настройки и данные пробы находятся в отдельном `-home`. Рабочие бинарники
и настройки сохраняются. Home → возврат в подключение предлагает продолжить ту
же пробу. Нормальный выход снимает блокировку нового запуска и удаляет её бинарники.
Статус завершения процесса не объявляется успешной проверкой изображения/управления.
Это ещё требует проверки пользователем; автоматической активации нет.

Android-адаптер читает URI и метаданные в фоне, сохраняет отдельную частную копию
с UUID-именем, проверяет её и SHA-256, затем атомарно меняет запись о выбранном
архиве. Ошибка или отмена сохраняет предыдущий выбор. При повторном открытии
экран заново проверяет копию, включая сохранённый хеш. Пересоздание Activity
подхватывает текущую задачу; после остановки процесса завершённая копия остаётся,
а прерванное чтение нужно повторить выбором ZIP. Собственные незавершённые копии
убираются при следующей задаче, если запись о предыдущем архиве читается.

Это структурная проверка кандидата, не проверка подлинности издателя, полной
исправности бинарника или его версии. Установленная оболочка, проверенный архив
и успешный запуск — разные состояния. Уже работающая установка не изменяется.
Подготовка среды с чистой установки, постоянное переключение установки с откатом
и автоматический показ мастера при первом запуске ещё предстоят. Пробный запуск
пока требует заранее подготовленной отдельной оболочки Runtime Test.
Связь Splore и миграция проектов/библиотеки также не закрыты.
Проверка кооперативно отменяется между чтениями; зависший document provider пока
не имеет таймаута. [Проверки архива](design/android-runtime-setup-29/README.md) ·
[Пробный запуск и скриншоты](design/android-runtime-probe-30/README.md).

Срез 0.0.21 реализует сохранённый выбор четырёх папок через Android SAF.
На полке: Select / «Папки». A выбирает назначение, X повторяет проверку,
B возвращает на полку. Для игр проверяем постоянное разрешение чтения и список
папки; для остальных назначений также создаём собственный уникальный `.tmp`,
пишем, читаем обратно и удаляем его. Недоступная новая папка не заменяет прежнюю.
После перезапуска записи сохранены, а состояние снова требует проверки доступа.
Смена назначения не переносит проекты и ресурсы; индексация игр появилась в
0.0.22–0.0.26, привязка Splore ещё не реализована. Выбор доступен для изменения, но открывается
с полки, а не принудительно при первом запуске. [Доказательства](design/android-folders-20/README.md).

Реализация следует [Android Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files):
tree URI и сохраняемые разрешения, без требования полного доступа к накопителю.
Идентификатор дерева остаётся непрозрачным для переносимого ядра; отображаемая
подсказка пути не становится Linux-путём для runtime.

Android lab 0.0.14 позволяет сохранить выбранный проект в отдельный внешний
`.p8` через системный диалог, с обратным чтением и сравнением байтов. Это полезный
выход из временного хранилища приложения, но ещё не постоянная папка проектов,
перенос всей библиотеки, синхронизация или резервная копия истории. Полный визард
по-прежнему нужен. [Проверка экспорта](design/android-export-13/README.md).

## Пользовательский результат

За короткий мастер выбрать расположение игр, загрузок Splore, собственных
проектов и постоянных данных/библиотеки, затем архив купленного PICO-8.
PikoNest сам распаковывает нужные файлы, готовит среду и проверяет запуск.
Ручная распаковка, терминал и самостоятельная установка зависимостей не должны
быть частью штатного сценария.

## Предлагаемые шаги

1. **Где хранить игры и творчество.** Показать рекомендуемые расположения с
   отдельным действием «Изменить» для каждого назначения. Можно выбрать общую
   базовую папку с подпапками или разные места, включая поддерживаемую SD-карту.
2. **Подключить PICO-8.** Объяснить, какой архив скачать, открыть системный выбор
   файла, проверить содержимое и совместимость, показать найденную версию.
3. **Подготовка.** Конкретные этапы: проверка → распаковка → подготовка среды →
   пробный запуск и возврат. Отдельно показать готовность Splore и его хранилища.
4. **Готово.** Короткая сводка расположений; «Мои игры» и «Создать игру».

Мастер использует тот же пиксельный язык и семантические действия контроллера,
что и редактор. Один основной выбор на экране; назад сохраняет уже выбранное.
Системные диалоги Android — платформенная граница: их управление контроллером
нужно проверить на поддерживаемых устройствах, не обещать непроверенную полноту.
Возобновление после закрытия приложения продолжает незавершённый шаг.

Редактор доступен при отложенном подключении runtime. Тогда явно показываем
«PICO-8 не подключён», а Test возвращает на нужный шаг мастера. Выбор архива
предлагается уже при первом запуске; прежнее предложение только при первом Test
остаётся запасным входом. Аккаунт PikoNest, курс и ввод имени проекта не обязательны.

## Папки и владение данными

| Назначение | Поведение |
|---|---|
| Готовые игры | Одна или несколько существующих папок; индексировать, не перемещать оригиналы. Редактирование через копию проекта |
| Загрузки Splore | Выбранное постоянное место для загруженных картриджей; доступность офлайн и отображение на полке проверяются отдельно |
| Мои проекты | Новые проекты с каноническим `.p8` и необязательными метаданными `.pikoos/` |
| Данные мастерской | Постоянная библиотека ресурсов, наборы и их метаданные; не одноразовый кэш |

Пример рекомендуемой структуры, а не обязательные имена: `PIKOOS/Games`,
`PIKOOS/Downloads`, `PIKOOS/Projects`, `PIKOOS/Data`. Уже существующие папки
можно подключить. Пересекающиеся корни не должны порождать дубликаты и циклы
индексации; внутренние файлы, библиотеку ресурсов и runtime не показывать как игры.

Исполняемые файлы и служебная среда runtime хранятся отдельно в управляемом
платформой месте. Карточка настроек различает постоянные данные и очищаемый кэш.
Все назначения доступны позже в настройках. Смена расположения предлагает
подключить существующую папку либо явно перенести данные с проверкой копии;
простая смена настройки не удаляет старые файлы и не обнуляет библиотеку.

На Android использовать подходящий системный выбор и сохраняемые разрешения.
Недоступная карта памяти, отозванный доступ или папка только для чтения требуют
понятного действия «Подключить снова» / «Выбрать другую» с сохранением записей.
Отмена выбора оставляет прежнее расположение. Не запрашивать полный доступ к
накопителю как безусловное требование продуктовой архитектуры.

## Какой архив скачать

Для **нынешнего экспериментального Android ARM64-бэкенда** инструкция:

> Скачай ZIP-архив PICO-8 для Raspberry Pi со своей страницы загрузки после
> покупки. Например: pico-8_0.2.7_raspi.zip. Выбери архив здесь — PikoNest подготовит
> его автоматически. Распаковывать вручную не нужно.

В 0.0.30 реализованы выбор, проверка ZIP и отдельная проба; полная автоматическая
установка ещё не готова.
Официальная [страница PICO-8](https://www.lexaloffle.com/pico-8.php) перечисляет
Raspberry Pi среди вариантов поставки. В архиве владельца проверены
`pico-8/pico8_64` и `pico-8/pico8.dat`; этот runtime запускался на Android в
[эксперименте](ANDROID_RUNTIME_POC.md). Архивы `amd64` и `i386` из той же покупки
не подходят этому ARM64-бэкенду. Номер 0.2.7 — проверенный пример, не вечное
требование к имени файла.

Допустимый тип архива определяет бэкенд и ABI устройства. Проверяем содержимое,
архитектуру и поддерживаемую версию, а не только суффикс имени. Другой Android
ABI и будущий Linux-бэкенд требуют своей проверенной инструкции. Пароль от
Lexaloffle не запрашиваем: пользователь передаёт уже скачанный им архив.
Проприетарные бинарники не включаем в дистрибутив PikoNest.

Импорт распаковывает в отдельное подготовительное расположение, отклоняет пути
за его пределами и неполные архивы. Переключает активную установку после проверки;
повторный импорт и ошибка не уничтожают предыдущий рабочий runtime или игры.
Если среде нужны дополнительные загрузки, показываем их размер/прогресс и
возможность повторить шаг; состав и поставка среды ещё требуют решения.

## Splore: требование и ещё не доказанная часть

Официальный справочник различает `-root_path` для картриджей и `-home` для
конфигурации и данных; Splore сохраняет загруженные BBS-картриджи для офлайн-игры.
Из этого не следует, что один `-root_path` перенесёт все загрузки Splore.
См. [справочник, разделы 1.8 и 1.11](https://www.lexaloffle.com/dl/docs/pico-8_manual.html).

Бэкенд должен доказать привязку или синхронизацию фактического хранилища Splore
с выбранной пользователем папкой. Android document URI нельзя передавать
Linux-процессу как файловый путь: монтирование/рабочая копия и согласование
изменений принадлежат адаптеру. При синхронизации ошибка записи не теряет
скачанное; показываем ожидающий перенос и даём повторить. Копии не перезаписывают
внешние изменения молча. Конкретная схема пока TBD.

## Приёмка мастера

- Чистая установка: папки и архив выбраны; официальный тестовый картридж
  запускается и возвращает в PikoNest без ручной настройки оболочки.
- Готовая игра находится в подключённой папке; новый проект и ресурс библиотеки
  сохраняются в соответствующих выбранных местах и доступны после перезапуска.
- Через Splore скачать ранее не загруженный картридж, вернуться, проверить
  наличие в выбранной папке и на полке; после перезапуска запустить офлайн.
  Для multicart отдельно проверить загрузку следующего картриджа.
- Неверный архив, отмена, нехватка места, прерывание подготовки и потеря доступа
  имеют возобновляемый путь; существующие игры, проекты и библиотека сохранны.
- На компактном и широком экране пройти действия PikoNest с контроллера;
  отдельно зафиксировать ограничения системного выбора файлов.

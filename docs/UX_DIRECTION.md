# PikoNest: единая мастерская на портативке

2026-10-04, [issue #2](https://github.com/EriArk/PikoNest/issues/2).
**Направление работ согласовано; конкретные новые экраны ещё требуют приёмки.**
Владелец уточнил: сначала исправить интерфейс и сделать его английским. Lab 0.0.66
начинает перенос с полок/меню/диалогов UX02; остальные инструменты пока прежние.
Основания —
[UX_AUDIT](UX_AUDIT.md). Реализация — [STATUS](STATUS.md); порядок и критерии —
[ROADMAP](ROADMAP.md), [BACKLOG](BACKLOG.md), [ACCEPTANCE](ACCEPTANCE.md).

Принятая основа сохраняется: характер PICO-8, читаемый пиксельный UI,
контроллер, Android first, обычный `.p8`, отсутствие обязательного героя.
Новые сетка, акценты, навигация и грамматика ниже предложены для следующих срезов,
но ещё не прошли визуальную/физическую приёмку. Старый документ целиком сохранён
в [UX_DIRECTION_HISTORY](UX_DIRECTION_HISTORY.md): версии и раскладки там —
история, а не конкурирующие актуальные правила.

## 1. Один продукт, три входа

| Вход | Задача | Граница |
| --- | --- | --- |
| Играть / Play | Местные игры, недавнее, избранное, запуск/продолжение | Не требует проекта, урока или импорта в редактор |
| Мастерская / Workshop | Свои проекты, создание и инструменты | Creator/Editor — контексты внутри, не отдельные продукты |
| Splore | Официальный мир PICO-8 | Официальный runtime, без собственного Discover-каталога |

Играть — домашний экран. Верхний переключатель входов доступен фокусом и меню;
плечевые кнопки могут ускорять, но не быть единственным способом перехода.
Настройки папок, runtime, контроллера и языка — в общем меню. Библиотека ресурсов
принадлежит мастерской. B идёт к реальному родителю, из дома — в Android-лаунчер,
не открывает произвольный последний проект.

```text
Играть → игра → Играть → runtime → та же игра на полке
             → Заглянуть внутрь → просмотр → Создать копию → проект
Мастерская → Новый проект / свои проекты → проект → инструмент
                                                 → Test → runtime
                                                        → тот же контекст
Splore → официальный Splore → исходный вход PikoNest
```

«Заглянуть внутрь» не меняет исходник. Первая правка требует явной копии в проекты;
неподдержанный импорт объясняется до обещания редактирования. Просмотр обложки
PNG, запуск PNG и извлечение редактируемого проекта — разные возможности.
Пустой проект доступен рядом с шаблонами, без обязательного имени/жанра.

Splore и публикация ещё требуют реализации по
[issue #1](https://github.com/EriArk/PikoNest/issues/1): подготовить обычный экспорт,
открыть официальный сайт; пользователь сам входит и отправляет игру. Аккаунт
сайта не является входом в PikoNest и не заменяет импорт купленного runtime.

## 2. Внутри проекта

Шапка: **имя проекта → инструмент**, рядом статус записи. Большой логотип — на
входе, не над каждой формой. Выбор инструментов — единый список с категориями
и избранным, не бесконечный ряд вкладок. Общие инструменты доступны в любом жанре.

| Раздел | Содержимое |
| --- | --- |
| В игре | Известные использования ресурсов, порядок, параметры; добавить/изменить/скопировать/удалить использование |
| Графика | Спрайты, карта, анимация, камера, фоны |
| Поведение | Ввод, состояние, условия/действия, эффекты по мере реализации |
| Звук | SFX и музыка |
| Ресурсы | Общая библиотека, извлечение и вставка |
| Код / Справка | Обычный Lua, объяснения и обучение по желанию |

Это карта продукта, не перечень готовых редакторов. Не заменять отсутствующий
инструмент неработающей кнопкой; объяснить текущую границу и сохранить данные.
Неподдержанные привязки доступны безопасному просмотру, не опасной перезаписи.

«В игре» — представление распознанного Lua/данных, **не формат сцены**.
Ресурс отличается от использования: правка пикселей влияет на обращения к ним,
перемещение одного использования не двигает другие. Камера — настройка диапазона
отрисовки, не игровой объект. Порядок world/screen и сброс камеры объясняются;
полноту списка использований произвольного Lua не обещаем.

Из спрайта — «Добавить в игру», из использования — «Изменить спрайт» с точным
возвратом. Фоновые слои подключаются через существующие операции без курсора Lua.
Простая игра из blank должна связывать ввод, состояние, цель, перезапуск, ресурсы
и звук инструментами. Это критерий завершения, ещё не достигнутый результат.

## 3. Визуальная система

Спокойный фон, заметный материал, один ясный фокус. Сохраняем палитру PICO-8,
резкие края, маленькие игровые реакции и картриджи на полке. Не добавляем
Material, стекло, тени, CRT-фильтр, плавающие панели или masonry. Цвета самой игры
не подчиняются правилам UI-акцентов.

| Роль | Предложение |
| --- | --- |
| Основная поверхность | PICO-8 1 `#1d2b53`; строки обычно без отдельных чёрных корпусов |
| Основной / вторичный текст | 7 `#fff1e8` / 6 `#c2c3c7`; ключевой текст не тускло-фиолетовый |
| Бренд, основное действие | 14 `#ff77a8`, умеренно; одно основное действие текущего шага |
| Фокус | 10 `#ffec27` + указатель/контур; заголовок и статус не конкурируют с ним |
| Выбранное вне фокуса | Галочка/метка и розовый маркер; активная вкладка подчёркнута |
| Чёрный 0 | Холст, код или обоснованная группа контрастного материала, не каждое поле |
| Ошибка / предупреждение | Красный 8 / оранжевый 9 с причиной и действием |
| Сохранение | Тихое «Сохранено» / явное «Есть правки»; жёлтый оставляем фокусу |

Сливовая полоса допустима на входе и в бренде, но не обязательна в каждом
инструменте. Рамка означает фокус, холст или сравнение; вложенные декоративные
рамки убираем. Цвет не единственный сигнал. Курсор холста, выбранный цвет и фокус
панели различаются формой.

### Сетка и текст: исходные значения пилота

Логическая сетка 4; наружный отступ 16 (12 компактно), расстояния 8 для связанных
элементов, 16 для групп, 24 для разделов. Строка действия 44–48; касание не меньше
44 dp. Проверить соответствие логических единиц реальному экрану, не увеличивать
вслепую каждый технический пиксель существующего Canvas.

Текущий **Monocraft** сохраняем в пилоте. Основной текст 18–20, заголовок
инструмента 24, входной заголовок 28; основной интерлиньяж 24–28. Проверить
кириллицу, `0/O`, `1/l`, скобки и длинные подписи. Лигатуры кода отключены,
колонки/курсор точны. Увеличение текста и отдельный режим длинной справки остаются
требованиями. Английский showcase не равен завершённой локализации Q07.

У списков одинаковые отступы, высота и маркер. У форм — подпись, значение,
единицы; объяснение выбранного поля. Полка — регулярная сетка/список. Полное имя
выбранной игры доступно рядом с обложкой, а не только в обрезанной строке.

Нижняя полоса — до четырёх актуальных подсказок. В редакторе обычно
`A действие · B назад · Start тест · Select действия`. Preview/палитра имеют
видимую кнопку с X на панели; остальные команды в меню. Не наслаивать несколько
рядов hints, статус и toast поверх материала. Подсказки показывают реальные
назначения устройства, не всегда буквы A/B.

### Адаптация

Почти квадратный экран: материал и короткая панель рядом, если читаемы.
Широкий: ограниченная ширина панели и больше материала, без растягивания текста.
Портрет/компактный: материал сверху, поля ниже с прокруткой/сохранением фокуса.
При нехватке места — подробности выбранной строки вместо всех справок сразу.
Шапка компактнее, основные действия доступны. Числа и предупреждение о замене
данных не обрезаются. Название можно сократить только с доступом к полному.

Игра/спрайты — целочисленный nearest-neighbor. 128×128 — экран игры, не редактора.
UI, insets и текст адаптируются отдельно, не уменьшаются общим масштабом.
Проверять квадратный, широкий, портретный варианты и компактную область около
360×480 логических единиц. Эмуляция размера на Retroid не доказывает другое устройство.

## 4. Грамматика контроллера

Таблица задаёт логический стандартный профиль. Физическое назначение/A-B convention
принадлежат input adapter; workflow получает смысловую команду. Подсказки и
обработчики используют один источник назначений. Touch вызывает те же команды.

| Кнопка | Общий смысл | Контекст |
| --- | --- | --- |
| A | Открыть / выбрать / подтвердить | На поле входит в правку; не увеличивает число и одновременно не сохраняет форму |
| B | Назад на уровень / отменить шаг | При выходе с правками выбор сохранения/отмены; просмотр не отменяет записанные данные |
| X | Подписанное вторичное действие | В каталогах избранное; в редакторе Preview/Play–Stop, на пиксельном холсте палитра. Профиль виден на панели |
| Y | Undo в изменяемой мастерской | В активном черновике его шаг, вне него операция проекта; в Play допустим фильтр. Не скрытое удаление |
| L/R | Соседний элемент текущего контекста | Страница, кадр, вкладка; не незаметный переход в другой продукт |
| Select | Действия контекста | Undo/Redo, копия, удаление, справка, выбор инструмента; есть фокусируемая кнопка |
| Start | Play / Test | При черновике «Сохранить и проверить / Продолжить правку», не молчаливая запись/игнорирование |
| L2/R2 | Необязательные ускорения | Есть путь без триггеров; смысловой Redo не превращается в движение курсора |

Ввод текста — отдельный подписанный профиль: A вводит символ, B отменяет,
«Готово» подтверждает имя; Start может быть его явным shortcut, но не запускает
игру за клавиатурой. Основные действия не требуют удержаний или комбинаций.

| Режим | Направления | A | B |
| --- | --- | --- | --- |
| Навигация | Фокус без изменения данных | Войти/открыть | Родитель |
| Правка значения | Черновик, оси подписаны | Завершить поле | Вернуть значение до входа |
| Холст | Курсор | Штрих/точка/этап области | Отменить незавершённую фигуру, затем выйти |

После поля остаётся черновик формы; «Применить» записывает целую операцию.
Направления повторяются при удержании, подтверждение/Test/удаление — нет.
Смена инструментов не записывает черновик молча. Redo доступен в Select с
названием повторяемой операции. Быстрый шаг значения может быть ускорением,
но не новым значением общего действия «следующий инструмент».

## 5. Общие сценарии редакторов

| Сценарий | Последовательность / результат |
| --- | --- |
| Создать / изменить | Список → форма/холст → видимый результат → одна завершённая операция → тот же элемент в фокусе |
| Копировать | Явно «Копия ресурса / использования / проекта» → место/имя при необходимости → подтверждение; просмотр ничего не записывает |
| Удалить | Название и влияние → подтверждение → Undo; удаление использования сохраняет пиксели |
| Выбрать ресурс | Тип, категория/избранное, миниатюра, размер/источник → A выбрать → исходное поле; B ничего не подставляет |
| Добавить в игру | Ресурс → положение/известная привязка/порядок → preview → применить → найти в «В игре»; неизвестный Lua не переписывается |
| Повторно изменить | Те же параметры/кадр/слой; текущие данные вместо сброса на preset |
| Библиотека | Явный состав и зависимости; вставленная игра независима от библиотеки; теги/избранное не меняют `.p8` |
| Объяснить | Необязательная справка и реальный API/Lua; закрытие возвращает фокус без правки |

**Не нужен диалог на каждый пиксель.** Штрих/заливка/фигура — одна автоматически
сохраняемая операция с Undo. Составная форма/вставка/замена — черновик, preview
и «Применить» завершают её целиком. Перед заменой занятой памяти, shared gfx/map
или связанного SFX — «сейчас/после», размер и известные использования. Нулевые
данные не объявляются свободными. Сравнение Lua раскрывается по желанию, а не
становится обязательным этапом простой игры.

| Состояние | Видимый смысл / выход |
| --- | --- |
| Сохранено | В `.p8` находится показанная завершённая версия |
| Есть правки | Форма/штрих ещё не записаны; применить, продолжить или отменить |
| Предпросмотр | Не меняет проект и не доказывает официальный runtime; B к правке |
| Ошибка записи | Черновик остаётся для повтора/копии; старый файл не запускается как новый |
| Пусто | Одно ближайшее действие создать/выбрать/импортировать, без обязательного урока |
| Lua не поддержан формой | Безопасный просмотр, пояснение границы PikoNest; это не «несовместимый картридж» |
| Ожидание | Что ожидается, отмена/возврат; повтор не создаёт второй проект/сеанс |
| Восстановленная правка | Вернуть черновик/фокус; опасное подтверждение показать заново |

История черновика и проекта различима. Постоянная история остаётся P04;
ограничения нельзя спрятать оформлением. Запись атомарна, внешние изменения
файла требуют разрешения конфликта, а не перетираются autosave.

## 6. Test и точный возврат

Сохранять выбранную версию и контекст: Play/Workshop/внешний лаунчер, проект,
инструмент, ресурс/использование, фокус, курсор, масштаб и прокрутку. Повтор
Start не создаёт второй запуск. Подтверждённый выход возвращает этот контекст,
без счётчика возвратов и ложного «игра проверена» по факту выхода процесса.

Различать «идёт запуск», «сеанс продолжается», «не удалось определить завершение».
При неизвестном сеансе — безопасные «Вернуться в PICO-8», «Проверить состояние»
и путь назад; проверка не закрывает процесс. Принудительное завершение, если
поддержано backend, — отдельное явное действие с объяснением возможной потери
игрового прогресса. Аудит не требует параллельного редактирования живого сеанса.

Нет runtime — к незавершённому шагу [настройки](FIRST_RUN_SETUP.md) и обратно.
Ошибка Lua — исходный текст и переход только к подтверждённому месту.
Неизвестный результат не означает успех. Меню обёртки согласуется с PikoNest;
внутренний UI официального PICO-8 не перерисовываем. Наблюдение/выход — контракт
backend, а не обещание View. Живой runtime без явного решения не завершаем.

Не называем всю графику «рисунком», каждый объект «героем», инструмент «шаблоном».
API, слоты и shared-память раскрываются там, где помогают принять решение.
Каталог RU/EN хранит целые фразы; API и пользовательские имена не переводятся.
Полный английский Q07 и выбор языков Q08 остаются отдельными задачами.

## 8. Требования инструментов сохраняются

Спрайты/карта: отдельные курсор, инструмент и цвет/тайл; масштаб не рисует,
области не обязаны быть 16×16, shared-память проверяется до записи. Анимация:
порядок/длительности/повтор, ручной кадр и play/pause, скорость отдельно от FPS.
Камера, параллакс, движение слоя и смена кадров различимы. Фоны: порядок,
повтор/стыки, прозрачность, конкретный слой в фокусе; персонаж не обязателен.

Звук: SFX/фразы/композиция, ноты/паузы, параметры шага/фразы, копирование,
прослушивание по действию и Stop. Выход останавливает пробу, фоновой музыки UI
нет, громкость устройства не включается автоматически. Общий SFX учитывает
музыкальные использования/каналы. Привязка к событию явная, распознавание
произвольного Lua не обещается. Требования и источники —
[PICO8_COMPATIBILITY](PICO8_COMPATIBILITY.md),
[VISUAL_EFFECTS](VISUAL_EFFECTS.md); подробные первоначальные требования сохранены
в истории этого документа.

Первый запуск выбирает папки игр, Splore, проектов и данных/библиотеки и готовит
правильный пользовательский архив runtime. Регистрация, урок, имя и подробный
remapping не блокируют начало. Создание/просмотр без runtime доступны; Test
возвращает к настройке. См. [FIRST_RUN_SETUP](FIRST_RUN_SETUP.md),
[ASSET_LIBRARY](ASSET_LIBRARY.md). Код, справка, обучение и optional keyboard
остаются доступны; обязательной клавиатуры или ручной сборки Lua нет.

## 9. Переход

Не переписывать все View сразу. UX01–UX05 связаны с существующими A/P/R/G/N/Q
в [BACKLOG](BACKLOG.md); границы пакетов — [UX_AUDIT](UX_AUDIT.md).
Сначала проверить общие правила на реальном пути, затем переносить компоненты.
Framework, доменную модель, идентификаторы и пользовательские файлы ради
оформления не менять. Библиотеки, категории и избранное сохраняются.
Недостающие базовые инструменты продолжаются по ROADMAP; аудит не создаёт
бесконечного отдельного этапа полировки.
